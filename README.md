# BiliMarketMonitor | B站市集商品价格监视器

一个监视 Bilibili 会员购市集商品价格的桌面小工具（PyQt5）。从文件导入商品 clusterId，依次查询每个商品的现价、近期均价和最近成交记录，以表格展示。

**免登录、无需 Cookie**——数据来自商品详情页前端调用的接口。

**致谢**：

感谢 moyu3739 大佬做的B站市集抓取，为本仓库提供了接口解析参考！[仓库地址](https://github.com/moyu3739/Bmarket)

## 功能

- **监视清单**：`data/watchlist.txt` 每行一件商品，格式为 `<clusterId> | <商品名>`，也可直接粘贴分享链接或纯数字 ID，程序会自动解析。清单既方便程序认 ID，也方便你按名字管理。
- **本地缓存**：商品的 clusterID、名称、缩略图保存到本地 SQLite（`data/cache.db`），缓存内容严格跟随监视清单——清单里少的补进来，多的删掉。之后启动时先整体扫描清单与缓存，立即显示所有已知信息，再对清单内商品逐个抓取最新价格；命中缓存的商品无需等待即可看到名称和缩略图。
- **依次轮询**：点击"开始抓取"后，依次（非并发）查询每个商品，默认间隔 2 秒（可在配置里调整）；单个商品查询失败不影响其他商品（自动重试 1 次），查询过程中显示进度（如 `查询中 3/12`）。中途可以暂停（两条商品之间生效）或直接停止，停止时已抓到的结果会保留。
- **表格展示**：

  | 缩略图 | 商品名 | clusterID | 现价 | 近30天均价 | 成交① | 成交② | 成交③ | 链接 |
  | --- | --- | --- | --- | --- | --- | --- | --- | --- |
  | img | 名称 | 10000008780 | ¥44 | ¥205 | ¥205 · 8天前 | … | … | 打开 |

  - 成交列显示"价格 · 相对时间"（如 `¥205 · 8天前`）；没有成交记录的商品显示"—"。
  - **近期成交加粗高亮**：发生在「多少小时以内」的成交用高亮色加粗显示，一眼看出哪些商品最近真的有人买（而不是挂着一堆陈年旧价）。阈值和颜色都在配置里，默认 24 小时内的成交用橙色。成交① 是最新一条，通常也就是被高亮的那条。
  - 点击"链接"列用浏览器打开商品详情页，链接由配置里的模板拼出（不保存原始链接）。
- **暗色模式**：一键切换深浅色主题，首次启动跟随系统设置，手动切换后记住选择。

## 用法

### 安装与启动

需要 Python 3.11 或更高（读配置用到 `tomllib`），依赖（`requests`、`PyQt5`）写在 `pyproject.toml` 里，用 pip 装即可。装好依赖后从仓库根目录运行 `python src/app.py`，两种方式等价，用哪个都行。

**方式一：普通 Python**——已有 Python 环境时最省事：

安装：

```bash
python -m venv .venv
source .venv/Scripts/activate      # Windows(Git Bash)；cmd/PowerShell 用 .venv\Scripts\activate
# Linux/macOS 改用 source .venv/bin/activate
pip install -e .                   # 读 pyproject.toml 装依赖；不加 -e 也行，区别只是会把源码复制进环境
```

运行：

```bash
python src/app.py
```

**方式二：[pixi](https://pixi.sh)**——不用自己管 Python 版本：

```bash
pixi run start
```

`pixi run` 会在环境没装或已过期时自动装好再运行，无需先手动 install。pixi 只是本仓库图省事选用的环境管理工具，程序本身不依赖它，`pyproject.toml` 里的 `[tool.pixi.*]` 两节删掉也不影响运行。

### 配置

配置一式两份，与你自己的监视清单一样，都放在 `data/` 下：`data/config.example.toml` 是随仓库分发的默认值兼格式参考，`data/config.toml` 是你自己的配置（**不会**被 git 追踪）。

```bash
cp data/config.example.toml data/config.toml   # 想改配置时
```

程序优先读取 `data/config.toml`，没找到有效值就回退到 `data/config.example.toml`，最终回退到代码内置默认值。可配置项：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `detail_url_template` | `https://mall.bilibili.com/neul-next/resell/detail.html?clusterId={clusterId}` | 商品详情页链接模板，`{clusterId}` 是占位符。表格里"打开"按钮打开的就是它拼出来的地址；官方页面改版时改这里即可 |
| `poll_interval_seconds` | `2` | 相邻两次请求的间隔（秒）。数据来自无文档的私有接口，**不建议**调小 |
| `retry_interval_seconds` | `1` | 单个商品查询失败后，重试前的等待时间（秒） |
| `request_timeout_seconds` | `10` | 单次请求超时时间（秒） |
| `deal_highlight_within_hours` | `24` | 成交发生在多少小时以内就加粗高亮。写成 `0` 表示关闭高亮 |
| `deal_highlight_color` | `#e07000` | 高亮成交用的文字颜色，支持 `#rrggbb` 和颜色名（如 `orange`）。默认值在深浅两种主题的表格底色下都看得清，自己换色时留意这一点 |

配置项写错时程序会忽略该项并在启动时打印提示，不会因此打不开。

### 配置监视清单

编辑 `data/watchlist.txt`，每行一件商品：

```text
# 以 # 开头的行、空行会被忽略；重复的 clusterId 只保留第一次出现
10000008780 | 淬羽赫默 角色亚克力立牌 进阶大礼包 规格：大礼包
10000004212
https://mall.bilibili.com/neul-next/resell/detail.html?clusterId=10000004245
```

三种写法都认，程序读进来后统一按 `<clusterId> | <商品名>` 规范化，名称未知时只写 ID。手工改完清单后点界面上的"刷新商品列表"同步即可。

### 界面按钮

- **添加…**：弹窗里粘贴商品 ID 或分享链接（一行一个，可一次贴多条），新商品会追加到 `watchlist.txt` 末尾并立即显示为新行。已存在的不重复添加；认不出的行会被忽略并在状态栏说明有几行。
- **删除选中**：把选中的商品从清单和缓存里一并删除（需确认）。
- **整理清单**：按规范格式重写 `watchlist.txt`，把链接、手写格式统一成 `<clusterId> | <商品名>`。
- **刷新商品列表**：重新读取 `watchlist.txt`，清单里新增的商品补成新行，删掉的移除，缓存同步跟随，已抓到的数据保留。
- **开始抓取**：逐个抓取清单内商品的价格；新商品连名称、缩略图一起抓，已缓存的商品复用本地信息只刷新价格。抓取完成后若学到了新商品名，会顺手写回 `watchlist.txt`。
- **暂停抓取 / 停止抓取**：平时是灰的，开始抓取后才可点击。**暂停**在两条商品之间生效（不打断正在进行的请求），按钮会变成"继续抓取"；**停止**直接中止本次抓取，已经抓到的结果保留在表格和缓存里，不会写回清单。

### 表格操作

- 点击"链接"列的"打开"→ 浏览器打开商品详情页
- 查询失败的商品，把鼠标悬停在商品名上可查看错误原因（悬停约 2 秒后弹出，免得光标扫过时一路弹提示）
- 支持按住 Ctrl / Shift 多选，配合"删除选中"批量清理

## 测试

界面测试跑在 Qt 的 offscreen 平台上，不需要显示器，也不会联网：

```bash
pixi run test
```

普通 Python 环境则先 `pip install -e ".[test]"`，再 `python -m pytest`。

测试有三条规矩（都写在 `tests/conftest.py` 里）：**不碰真实 `data/`**（数据路径整体指向临时目录，另有会话级看门狗比对 `data/` 指纹，被改动过就 fail）、**不联网**（`requests` 一律被换成抛错）、**不弹窗**（`QMessageBox` 与 `webbrowser.open` 一律被拦下并记录）。

## 架构

```text
BiliMarket/
├── pyproject.toml      # 依赖声明 + pixi 配置 + 启动/测试任务（后两者可选）
├── data/               # 数据文件
│   ├── config.example.toml    # 配置默认值（随仓库分发，可复制为 config.toml 后修改）
│   ├── config.toml            # 个人配置（可选，不入库）
│   ├── watchlist.example.txt  # 监视清单示例（模板）
│   ├── watchlist.txt          # 监视清单（用户维护，程序会规范化写回，不入库）
│   ├── cache.db               # 本地缓存（首次运行后自动生成，不入库）
│   └── cache.db.bad-<时间戳>   # 缓存损坏时的备份（自动改名留档，不入库）
├── tests/              # pytest 测试（界面走 offscreen，见「测试」一节）
│   ├── conftest.py     # 临时数据目录 / 无头 Qt / 看门狗 / 拦网络与弹窗
│   ├── test_app.py     # 主窗口渲染与按钮流程、PollerThread、缩略图线程
│   ├── test_client.py  # 请求形态与各类失败的统一出口
│   ├── test_config.py  # 配置优先级与逐项校验
│   ├── test_links.py   # 清单解析、去重、规范化回写
│   ├── test_parser.py  # 响应解析与全路径判空
│   ├── test_store.py   # SQLite 缓存随清单增删、设置项
│   └── test_theme.py   # 样式表、占位文字配色、系统深浅色判断
└── src/
    ├── app.py          # 入口：PyQt5 主窗口 + QThread 轮询调度，汇总各模块的降级提示
    ├── client.py       # API 封装：fetch_cluster(cluster_id)，入参自检、失败统一 ApiError
    ├── parser.py       # 响应解析：提取名称/价格/均价/成交/图片，全路径判空 + 出口结构归一
    ├── links.py        # 清单读写：解析 clusterId / 名称，编码回退、名字清洗、规范化回写
    ├── config.py       # 配置读取：data/config.toml 优先，config.example.toml 兜底，逐项校验
    ├── store.py        # SQLite 缓存：clusterID / 名称 / 缩略图，随清单增删，损坏自动备份重建
    └── theme.py        # 主题：深浅色 QSS，跟随系统（Windows 注册表）
```

数据流：`data/watchlist.txt` → `links.py`（解析/去重/规范化）→ `store.py` 同步缓存并显示已知信息 → `client.py`（请求接口）→ `parser.py`（判空提取字段）→ `app.py`（刷新价格、写回缓存与清单）。

配置只在启动时读一次（`config.py`），拼接详情页链接和轮询间隔都以它为准。

轮询放在子线程（`QThread` + 信号槽），每条结果回传主线程刷新表格，界面不会假死。

## 说明

- 本工具只做价格监视，不涉及下单。
- 数据来自无文档的私有接口，本工具默认轮询间隔 2 秒，请勿改成高频轮询。
- 私有接口字段随时可能变化，属正常现象；解析层对每条取值路径都做了判空，字段消失时对应位置显示"—"而不是报错。
- 本项目与哔哩哔哩官方无关，非官方工具。

### 出问题时的降级行为

每个模块都自己检查输入、不依赖调用方"保证"传进来的是合法数据。异常一律**降级 + 留痕**，不弹窗打断：

| 情况 | 表现 |
| --- | --- |
| 接口响应结构变了（字段缺失、类型不对） | 该商品显示"—"，鼠标悬停商品名看原因，其他商品照常 |
| `watchlist.txt` 被改成 GBK 编码 | 按本地编码读入并在状态栏说明，不是直接崩 |
| 清单里有认不出的行 | 跳过这几行并在状态栏提示，其余照常载入 |
| 商品名里有竖线或换行 | 写回清单前清洗，避免写出一行坏清单 |
| 缓存 `cache.db` 损坏 | 改名备份为 `cache.db.bad-<时间戳>` 后重建空库，状态栏提示；已抓到的数据重新抓即可 |
| 配置里写了 `inf` / `nan`、模板不是 http(s) 链接 | 该项退回默认值并打印一条警告，其他配置照常生效 |
| 成交时间是认不出的格式（如绝对日期、错别字） | 照旧显示原文，只是不高亮——宁可少标一处，也不拿猜出来的新旧误导人 |
| 配置里的高亮色认不出来（如 `orangejuice`） | 退回默认橙色并打印提示，不会静默变成"高亮没生效" |

缓存只是加速用的：它坏了、名字写错了都不影响程序启动，重新抓一遍就能补回来。清单 `watchlist.txt` 才是唯一标准。
